Add a tool to agent/tools/, in a file of its own.

  agent/tools/<name>.py

One tool per file, and never a module holding several. Each of those files is a
node in the interface, so six tools in one file is one box where there should be
six — and a person looking at the agent cannot see what it can do. If agent/tools/
does not exist yet, create it as an ordinary package.

A tool is a thin wrapper. It takes its identifiers from the agent's context object,
never from arguments the model produced, and it calls existing project code rather
than containing logic itself.

If the tool needs behaviour that does not exist yet, say what is missing and stop.
Do not invent a service.

Produce:
  the function in agent/tools/<name>.py, with a docstring the model will read as
  its description
  registration wherever the agent's tools are declared
  a test that calls the function directly with a fake context

A module that defines no public function is a helper rather than a tool, and it is
not a node. That is fine, and it is not what this task produces.

If the tool reaches an external system, the test must use a fake, never the real
one.
